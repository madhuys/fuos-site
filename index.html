What's inside // no mock-ups

Every window is a real app. Every document is a real file.

No look-alike editors, no simulated terminals, no placeholder data. These are the apps you get, and the agent works in them with you.

01 // The desktop

The OS itself is a tool

The agent sees which windows are open, and opens, arranges and closes apps for you.

  • Windows snap and resize; desktop pages, widgets and sticky notes stay where you left them.
  • The Assistant docks beside whatever you are working on.
  • Find anything from one search: files and their contents, chats, mail, calendar, settings.
02 // The browser

A real Chromium you can watch

Chromium runs in its own sandbox and streams to your desktop.

  • The agent does web tasks in the tab you are watching, typically 0.1 to 0.5 s a step.
  • Tabs and profiles survive a restart.
03 // Office, code, notebooks

Documents, code and data, for real

Every document is a real file in your workspace, with version history and undo for what the agent changed.

  • .docx, .xlsx and .pptx in Collabora Online (LibreOffice), with the Assistant docked beside them.
  • A VS Code-compatible editor (OpenVSCode Server), a real terminal and JupyterLab.
  • draw.io and Excalidraw diagrams, webmail, calendar and contacts.
04 // Studios

Bots, workflows, widgets and apps

Build with the same agent, in the same desktop.

  • Workflows on a visual canvas, run on a schedule or by an event.
  • Widgets for the desktop, and bots with their own instructions.
  • Apps in App Studio: each one a git repo, previewed live.

Security // under the paint

Loud on the surface. Locked down underneath.

An agent with real tools needs real limits. In FUOS they are enforced by the system, not by asking the model nicely.

A sandboxed agent

The agent, JupyterLab and the apps it builds run in a Linux sandbox (bubblewrap): your home is read-only, credentials are hidden, and it gets its own process space.

Approvals it can't talk around

Sending mail or messages, changing your calendar, running workflows or creating a GitHub repo needs a one-time grant that only your Approve creates. The platform checks it, not the model.

A log you can verify

Every action goes into a hash chain signed with your machine's Ed25519 key. Export it and verify it offline.

Encrypted keys

The API keys and passwords you give FUOS are kept in an AES-256-GCM encrypted vault.

No agent loop of our own

FUOS speaks open protocols to the agent you pick. Extensions the agent plants for itself are set aside at every start.

Repairs itself

A watchdog restarts an app service that stops answering and tells you if one keeps failing. It never restarts the agent in the middle of your task.
